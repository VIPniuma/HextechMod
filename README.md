# HextechMod（海克斯）

PEAK 的 BepInEx 模组：海克斯强化 + 主动技能与能量系统 + 代币商店（海克斯抽奖）+ 行李箱开箱抽奖。

## 玩法

- **开局什么都没有**：初始不带任何技能、不带任何强化，全靠局内抽。
- **登岛强化**：刚进游戏、在海滩（第一个阶段）落地时，送一次 3 选 1。
- **点燃篝火才能抽**：每个阶段的篝火被点燃（真正推进阶段的那一次）后，再给自己一次 3 选 1，选定后立即生效，可叠加的强化会累计层数（乘法叠加，见「品质与叠加」）。
- **跳过不等于放弃**：3 选 1 面板按 `ESC` 只是先收起来，这次机会**不会丢** —— 没选的会一直记在账上，
  按 `Y`（`界面.重新打开三选一`）随时能叫回来接着选。如果一直不选，下一次点燃篝火时会
  **连同新的一次一起弹出来**（跳过 2 次就攒成 3 次连选），以此类推；回到机场开下一局才清空。
- **中途加入自动补足**：一局打到一半才进来的队友（或者半路重连回来的）不会白白少抽几次：
  3 选 1 按**关卡进度**补 —— 推到第 S 段就补 S+1 次（登岛 1 次 + 1~S 每次篝火各 1 次），面板依次弹出，点到选完为止；
  商店代币按**已进行时长**补 —— 刚进局时问一下房主「这局打了多久」，把错过的那些「每分钟 1.5 枚」补上。
  3 选 1 补的次数用的就是「每个阶段只发一次」的那套标记，所以从头打到这里的玩家不会被重复发；
  代币补的是「房主时长 − 自己时长」，自己那份仍在照常累积，也不会重复发。
  （代币那部分需要房主也装了这个 mod：房主没装就等不到答复，3 选 1 照样会补。）
- **阶段三选一只出正面词条**，负面词条只会从下面说的开箱抽奖里被随到。
- **行李箱改成抽奖**：打开行李箱不再按原样刷物资，而是按「本来要刷几件」抽几次奖，
  每一次的结果是**物资**、**海克斯**或**商店代币**（1 ~ 20 枚）；抽到的海克斯是随机的、**可能是负面的**。
- **商店**：局内每分钟发 1.5 枚代币，按 `L` 打开商店（再按 `L` 或 `ESC` 关闭）。商店分 5 类：海克斯抽奖 + 普通/精良/稀有/传说物资。
  抽奖按品质定价（青铜 18 / 白银 45 / 黄金 90，每档整局限购 1 次），物资按**稀有度 + 用途**定价
  （绳子、踏板菇这类「有它没它差很多」的功能道具明显更贵，见[商店](#商店)里的「定价怎么算的」），
  卡片直接用游戏物品自带的图标。
- **抽奖动画**：只有**海克斯**会播那段 CS2 开箱式的横向滚动动画（商店买抽奖券、开箱抽到海克斯时），
  一次约 2.6 秒，滚完停在结果上。开箱抽到的**物资与代币不播动画** —— 一箱动不动十来件，
  件件都看一遍滚动条太拖时间，东西直接掉在箱子原位、代币直接进账，结果只在播报里写一句。
  动画**排队播放** —— 上一个还没演完就又开了个箱子，新的会排在后面接着演，不会被打断、也不会被吞掉。
  动画纯粹是演出 —— 结果在开动画之前就结算完了，跳过/中途退出都不影响实际收益。
- **主动技能**：抽到「海克斯：XX」词条才会解锁对应技能，按 `G` 释放、`H` 切换，消耗能量并带冷却。能量上限 100，每秒回复 7 点。
  已解锁的技能会单独排在**屏幕正下方的技能 HUD** 上（详见[主动技能](#主动技能)）。
- **回到机场即清空**：一局结束回到机场时，本局的词条、层数、技能、能量、代币以及被改过的角色数值全部还原。
- **右侧 HUD**：实时显示能量、当前技能和本局已获得的词条，每条都带上当前层数的实际效果。
  一页最多放 7 条，超过就自动分页轮播（**10 秒翻一页**，循环播放；标题栏会显示 `海克斯 HEX · 1/2` 这样的页码）。
  面板挡画面时按 `K` 收起，只留一颗小提示（`K 打开菜单` / `L 打开商店` / 当前代币数），再按 `K` 展开。
  展开时标题栏右侧会写一句 `按 K 收起面板`，不用翻说明也知道能收。
- **每个人抽自己的**：面板、技能与词条都是本地玩家私有的，不共享抽卡池，也不共享强化效果。
  只有行李箱抽到的**物资**是所有人共享的（由房主生成，谁都能捡）。
- **防挂机**：在**点着的**篝火 25 米范围内连续站满 **3 分钟**（默认），就叫一只原版蘑菇僵尸出来并**锁定**你 ——
  想靠着篝火挂机是挂不住的。走出范围**不会**立刻清零，而是按同样的速度往回退（退到 0 为止）—— 偶尔出去拿个东西、
  绕一圈再回来是接得上的，真一直站着不动才会攒满。召唤过一次之后计时也归零，继续站着就每 3 分钟再来一只。
  只会数**和你在同一张场景里**、并且**真在烧**的篝火：机场进出场那一片不算（机场里那种一直亮着、其实不冒火苗的
  装饰篝火也不算），所以刚上机 / 刚落地不会莫名其妙被招僵尸。
  判定由**房主**那台机器统一做（往世界里生成怪物只有房主做得了），所以只要房主装了模组，全房间都会生效；
  单机（自己就是房主）同样有效。范围与时长的默认值见配置里的 `防挂机` 分组，也能整个关掉。

## 快捷键

| 按键 | 作用 |
| --- | --- |
| `G` | 释放当前技能（还没有技能时会提示去抽取） |
| `H` | 在已解锁技能之间切换 |
| `K` | 展开 / 收起右侧海克斯 HUD（收起后只剩小提示，不挡画面） |
| `Y` | 重新打开还没选的三选一面板（按 `ESC` 只是先收起来，机会不会丢） |
| `N` | 「死而复生」：把一名已死的队友复活到你面前（抽到该词条后才有） |
| `L` | 打开/关闭海克斯商店 |
| `F9` | 打开模组配置面板（和 `ESC` → 设置 里最上面那行「海克斯模组设置」是同一个面板）；**面板列表底部的「商店调价」就是逐件改价的地方** |
| `F10` | **遇到 bug 时按这个**：把本机状态、词条、配置和两份日志的尾部打包上传，几秒后屏幕上出现一个 6 位编号（已自动复制），把这个编号发给作者即可 |
| `ESC` | 关闭商店 / 先收起三选一面板（走游戏原生的窗口取消，和游戏自己的界面一个手感；收起**不消耗**这次机会，按 `Y` 随时回来接着选） |
| 鼠标左键 / `1` `2` `3` | 在三选一面板中选择 |
| 鼠标左键 / `1`~`9` | 在商店中购买当前分类的前 9 件（不关闭面板，可连续买） |
| 滚轮 / 拖动右侧滑块 | 在商店里上下浏览全部商品 |
| `T`（商店里） | 调价的快捷入口：进出**调价模式**，和 `F9` 面板底部那段是同一张表，详见[商店](#商店) |
| 鼠标左键点卡片右下角「刷新」 | 换掉这一张强化，每张卡每次机会限 1 次（按 `ESC` 收起来再打开也一样：牌不重抽、次数也不重置） |
| `空格` / `回车` / 鼠标左键 | 跳过正在播放的抽奖动画 |

两个面板打开时都会自动解锁鼠标（`Cursor.lockState = None`）并把 `usingEmoteWheel` 置位，
关闭后恢复原来的鼠标状态，所以选择完全可以用鼠标点。
面板会挂进游戏原生的窗口列表（`MenuWindow`），所以 `ESC` 交给游戏自己处理：窗口被关掉之后，
界面在自己的 `Update` 里发现「窗口没了」就跟着收起，不会出现「界面还在但鼠标已经锁回去」的状态。

## 品质与叠加

海克斯分四档品质，品质同时决定**一次加成给多少**：

| 品质 | 一次加成 | 徽章 | 颜色 | 抽取权重 |
| --- | --- | --- | --- | --- |
| 青铜 | 8% | ● | 古铜色 | 60 |
| 白银 | 12% | ◆ | 银白 | 22 |
| 黄金 | 16% | ★ | 金色 | 10 |
| 传说 | 20% | ※ | 紫色 | 1（`海克斯.传说词条权重`，0 = 抽不到） |

（2026-09-13 全量削弱：10 / 15 / 20 / 25 → 上面这组，游戏整体难度回调。）

**传说档是头奖**：权重只有 1，也就是每格约 0.1%，而且商店的抽奖券开到黄金为止 ——
想要传说只能靠登岛/篝火的三选一与开行李箱碰运气。传说词条**不挂「代价」**，
它们的代价写在自己的玩法里（骷髅不再留下骸骨、复活机会只有一次）。

重复获得同一条词条时按**乘法叠加**：新的一层加在「已经拿到的加成」上，而不是加在基础数值上。

```
12% 之后再得 12%  →  12% + 12%×12% = 13.44%
再来一次          →  13.44% + 13.44%×12% = 15.05%
```

即第 n 层的累计加成 = `v × (1+v)^(n-1)`（`v` 是该品质的一次加成）。
所以「×2」并不等于两倍加成 —— HUD 里每条词条下面显示的就是**按当前层数算好的实际效果**。

加成数值都写在品质表里（代码里是 `HextechQualityMath`），词条说明里的数字由品质自动填，
不存在「说明写 10%、实际乘 1.15」这种对不上的情况。

不走品质表的只有五类：

- 固定值 / 机制型的词条：人人为我 60 点额外体力、拉拉手（20 点）、厨师、背包客、围炉谈心、送葬人、收藏家、资本家、骨质疏松、赌徒，以及负面里的手滑（投掷蓄力打折）、夜盲（周期性失明）、拖后腿（对队友的距离光环）。
- 整个传说档：骨质疏松 / 死而复生 / 不死鸟 / 海克斯：机械手 —— 效果写死、不挂代价，稀有度全靠权重压。
- 镜像成对的「状态积累」词条：坚韧之躯 -25% / 玻璃体质 +25%，两边必须一正一负对应。
- 专项状态抗性：皮糙肉厚 -30% / 抗毒体质 -30% / 隔热层 -20% / 破咒者 -20%，
  只管一种状态、所以比通用版的 25% 重一档，一正一负对应不上，也不走品质表。
- 半条坏处、半个好处的「冷血体质」：代价是夜间寒冷 +20%，赔偿是灼热（晒伤）积累 -50%
  —— 赔偿这一半和上面四条专抗走同一套削减，按层取幂。
- 代价型负面词条 —— 数值是「代价」，故意比同品质的正面加成重。

**黄金词条一律带一条「代价」**：说明末尾会多出一句红色的 `代价：…`（三选一面板、HUD、商店卡都会显示），
效果和正效果一起生效，同样按层乘在基准值上、回机场按基准整体还原。
代价的数值写死在词条里（8% ~ 25%），故意比品质数值小一档 —— 黄金是用来换玩法的，不是白送的。
唯一一条不挂代价的是**赌徒**（效果写死、没有可乘的数值），它是从传说档调上来的。

## 词条一览

词条分三类：**永久收益**会出现在登岛/篝火的三选一和商店里；**限时爆发**（护盾、无限耐力、无敌、大治疗、士气提升）
与**负面**词条一样，只在开行李箱抽奖里出现 —— 能选到的永远都是能一直吃到最后的永久收益。
下表里的百分比是**第一次**获得的数值，之后再拿到同一张就按上面的乘法叠加。

定级只按「这条词条能把一局游戏变轻松多少」，不看实现复杂度：

- **青铜**：单属性小加成、一次性小补给、情境型机制。
- **白银**：核心资源（耐力 / 伤势 / 寒冷 / 负面状态）削减、状态消退加速、主动技能解锁、纯收益机制。
- **黄金**：改变玩法的永久机制，一律带「代价」（只有「赌徒」例外）。

## 商店

局内每分钟自动发 1.5 枚代币（可在配置里改速率），**代币是连着涨的** —— HUD 与商店右上角都显示到一位小数
（1.5/分 = 每秒 +0.025，攒够一整枚才算攒下一枚；买不起时账上那点零头会留着），按 `L` 打开商店。顶部是分类，下面是**一整块可滚动的商品网格**：
所有商品一次铺开，滚轮下滑浏览全部（右侧有滑块，也可以拖着走），鼠标点卡片就买，买完不关面板，可以连续买。

| 分类 | 内容 | 稀有度基准价 |
| --- | --- | --- |
| 海克斯 | 抽奖券，买下后播开箱动画，每档整局限购 1 次 | 18 / 45 / 55 / 90 代币 |
| 普通物资 | Common | 5 |
| 精良物资 | Uncommon / Rare | 8 ~ 12 |
| 稀有物资 | Epic / Legendary | 16 ~ 20 |
| 传说物资 | Mythic / RidiculouslyRare | 24 ~ 30 |

物资的实际售价还受**功能底线价 / 顶价**和一件一算的**个体微调**影响，见下面「定价怎么算的」。

### 海克斯抽奖

商店不再直接卖道具，只卖抽奖，按品质分档：

| 商品 | 价格 | 限购 | 内容 |
| --- | --- | --- | --- |
| 海克斯抽奖 · 青铜 | 18 代币 | 整局 1 次 | 随机 1 项正面强化，以青铜为主，小概率直接出白银/黄金 |
| 海克斯抽奖 · 白银 | 45 代币 | 整局 1 次 | 保底白银（白银 75% / 黄金 25%） |
| 海克斯抽奖 · 黄金 | 90 代币 | 整局 1 次 | 必定出 1 项黄金强化 |
| 强化礼包 · 三连 | 55 代币 | 整局 1 次 | 一次开出 3 项互不重复的正面强化，比单抽划算 |

限购是按「本局」算的，回机场清空后下一局可以重新买。买过之后卡片置灰、提示「本局限购，已买过」，
所以一局最多从商店拿到 6 项强化（3 张券 + 三连礼包），想再要多只能靠点燃篝火和开行李箱。
池子被抽空（该档位已经没有可给的词条）时卡片同样会自动置灰，不会白花钱。
抽到的词条**立即生效**，动画只是把结果演给你看；停下时结果条上会同时给出**词条名字**与**它当前层数的实际效果**，
不用再去翻 HUD 才知道刚才抽到的是什么、干什么用的。

### 物资

物资表是打开商店时扫描游戏物品池得到的（`LootData.AllSpawnWeightData` 的全部条目），所以**几乎所有物资**都能买：
不卖图鉴（`Guidebook`）、石头（`Stone`）、怪物身上的道具（`MobItem`），也不卖金神像这类成就收集品，
另外单人局刷不出来的东西（需要多人配合触发）在单人局里也不会出现。物资买下后掉在你面前，是共享的，谁都能捡。

卡片上的图标直接取游戏物品自带的 `Item.UIData.icon`；代币不够时图标会压暗，一眼看得清买不起。

代币回机场清零，所以商店是纯局内经济。价格是**查价那一刻**算出来的，不是建表时写死的，
所以抽到「讲价高手」之后立刻回到商店，卡片上的标价就已经是五折了。
`商店.物价倍率` 是全局物价倍率（默认 `1.0`），想整体调低让游戏简单一点用它就行。

想**逐件调价**的话，主要入口在 **`F9` 配置面板**：滚到列表最底下的「商店调价」段，
每件商品一格（面板按两列排），左边是名字和默认价、右边是 `− 现价 ＋`。
点一下 `−` / `＋` 改 1 枚（按住 `Shift` 一次 5 枚），改的是这件商品自己的基础价（范围 1 ~ 999，
和全局倍率叠加）；点中间那串数字单独恢复这一件的默认价，表头下面那行右边的「重置全部」一键全恢复。
商店里按 `T` 也能进调价模式（同一张表，卡片上直接多出 `−` / `＋`），喜欢在店里改的话用它更快。
改完立刻生效，表会存进 `BepInEx/config/HextechMod.prices.txt`（单独一个文件，不塞进 `.cfg`）。
**联机房里只有房主能调价**：客户端在面板里看到的是「商店调价 · 联机时只有房主能改」，
按钮点了只会弹一句提示；房主改完会把整张表广播给全房间，中途进房的人也会自动向房主补齐一份，
所以房间里所有人看到的价钱是一致的。物资那几百行要等游戏把物品表扫出来（进游戏开过一次商店）才会列出来，
抽奖券那几档随时都能调。

调好一版价格之后可以**存成预设**：调价模式（商店里按 `T`）右下角、`F9` 面板「商店调价」那一段里，
都有「保存为预设」和「选择预设 ▾」两颗按钮。

- **保存为预设**：把**现在这一版**价格存成一份，自己起名字（最多 12 个字，同名整份覆盖）。
  一份预设包含**逐件调价表**和 `商店.物价倍率` / `商店.功能溢价` / `商店.每分钟代币` 三个数值项 ——
  它们是一起决定「这件东西到底卖多少」的，只存一半的话换过去还得手动补倍率。
- **选择预设 ▾**：列出「默认配置」+ 所有存过的预设，点一份整张表就换过去（数值项一起）。
  点「默认配置」= 调价全部清零、三个数值回到模组默认值。每份预设右边有个「删除」，点两下确认才真删。
- 表存在 `BepInEx/config/HextechMod.prices.presets.txt`，和逐件调价表同一个目录。
- **更新不会吃掉你已经调好的价**：装上带这个功能的这版之后第一次进游戏，模组会先把更新前的价格设置
  **自动备份**成一份预设「自定义价格表1」，然后才走原来那套「配置版本对不上就把数值刷回默认值」。
  所以老玩家更新完进游戏，选择框里就躺着一份自己原来的价格，点一下就回来了。以后每次更新都不会重复备份，
  想要新的一份在旁边点「保存为预设」就行。

### 定价怎么算的

一件物资的默认价 = **稀有度基准价**，再被**功能底线价**抬一手（只抬「很有用却很便宜」的那批）、
被**顶价**压一手（只压「作用配不上价签」的那几件），最后乘一件一算的**个体微调**；
逐件调价表仍然可以直接覆盖它（见上一段）。

| 稀有度 | 普通 | 精良 | 稀有 | 史诗 | 传奇 | 神话 | 荒诞 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 基准价 | 5 | 8 | 12 | 16 | 20 | 24 | 30 |

和最初那版（`4 / 7 / 12 / 18 / 28 / 45 / 70`）比：底下两档各抬 1 枚（以前 4 枚就能买一件普通物资，
比一次抽奖还便宜，商店等于白送），稀有及以上整体下调（一局也就几十枚代币，70 枚一件的价签等于「买不到」）。
也就是说，除了下面那批「很有用却很便宜」的功能道具，整店的价只降不涨。

**功能比稀有度更值钱**：稀有度只说明「这东西刷出来的概率」，说不清「这东西能干什么」——
一捆绳子能让整队翻过一面墙，一株踏板菇能凭空造出一块落脚点。所以反过来看道具身上挂了哪些游戏组件，
给这类道具定一条**底线价**；反过来，作用配不上价签的再给一条**顶价**：

| 归类 | 认得的东西 | 底线价 |
| --- | --- | --- |
| 位移 | 绳 / 枪绳 / 藤枪 / 气球 / 魔豆 / 踏板菇 / 滑翔翼 / 喷气・火箭背包 / 降落伞 / 攀爬钉 / 可放置类 | 30 |
| 救援 | 护符（大治疗 / 无限体力 / 二段跳 / 复制）、救援钩 | 30 |
| 容量 | 背包、号角、护盾玩偶 | 25 |
| 光源 | 提灯 / 信号弹 / 蜡烛 / 火把 / 炸药 / 蜂巢 / 雪球 / 曼德拉草 | 20 |

| 归类 | 认得的东西 | 顶价 |
| --- | --- | --- |
| 滑翔翼 | 挂 `Glider` 的那件 | 22 |
| 一束气球 | 挂 `Balloon` 的那件 | 15 |
| 食物（纯补给） | 蘑菇 / 浆果 / 袋装食品（没有别的功能时才走这档） | 基准价 ×0.8，且不超过 12 |

底线是**补差价，不是涨价**：只有按稀有度算下来比它便宜的才被补到底线 —— 一株稀有度「稀有」的踏板菇
从 12 涨到 30；而荒诞稀有度的提灯本来就 30 枚、比光源那条底线（20）还贵，就一分不动。顶价只管反方向：
按稀有度算出来比顶价贵的才被压下来，本来就便宜的（普通档的食物）原样不动。所以涨价只落在
「作用很大、价格却低得离谱」的那一批、降价只落在「作用配不上价签」的那几件身上，整家店不会一起变贵。
价格表是**从上往下第一条命中的生效**，不叠加也不取最高 —— 所以滑翔翼、一束气球那两条排在「位移」前面
（绳子兼照明之类本来就少，叠加出来的价格既没法解释也没法调）。

强度由 `商店.功能溢价` 控制：`0` = 底线与顶价都不管、只按稀有度定价，`1` = 默认（补到 / 压到上表的价），
`2` = 把这份差距再翻一倍。

**同档不同价**：每件物资再按 prefab 名算一个 ±15% 左右的稳定浮动（`0.88 ~ 1.24`）。
用名字哈希而不是随机数 —— 价格是全场统一的事，房主和每个客户端必须算出同一个数，重启游戏也不能变，
否则调价面板里的「默认价」每次开机都不一样。

归类全按组件猜（游戏没给道具标「功能」这种属性），所以进游戏开过一次商店后，
日志里会打一句 `商店定价：共 N 件，M 件按功能改过价（…）；最贵：…`，
想知道某件道具被算成了哪一类，看这行比一件件翻商店快。

## 行李箱抽奖

打开行李箱时：

1. 先算出这个箱子原本会刷几件物资（`Spawner.GetSpawnSpots`），再加上「幸运旅客」的层数，得到抽奖次数 N。
2. 原版掉落整体关掉（对 `Spawner.SpawnItems` 做了前缀拦截），改成抽 N 次奖。
3. 每次抽奖依次判定：
   - 按 `行李箱.正面海克斯概率`（默认 2.5%）判**正面**海克斯 → 在正面池里按品质权重抽 1 个，直接生效，**不给你选**；
   - 没中就按 `行李箱.负面海克斯概率`（默认 1.5%）判**负面**海克斯 → 在代价词条池里抽 1 个，同样直接生效、不给你选；
   - 都没中就按 `行李箱.出代币概率`（默认 10%）判代币 → 随机 1 ~ `行李箱.代币上限`（默认 20）枚商店代币；
   - 都没中 → 拿到原本该刷的那件物资。
   正面 / 负面是**两次独立判定、各自成池**（抽中哪一半，就只在那半边的池子里按品质权重挑，所以概率能分别调），
   两边加起来就是「开箱出海克斯」的总概率（默认 2.5% + 1.5% = 4%）。负面池空了（被禁掉 / 都抽满）时退一格给正面。
4. 抽到的物资由房主在箱子原位生成，所有人可见可捡；抽到的海克斯是开箱者私有的。
5. 所有结果**当场结算**（物资已生成、海克斯已生效）：抽到的物资直接掉在箱子原位、代币直接进账，
   这两样都不播动画；只有抽到海克斯的那几次会播一段滚动动画，把结果演出来。

复活箱（`RespawnChest`）保留原版行为，不受影响。

按默认配置，每个抽奖位抽到的东西大致是：

| 结果 | 每格概率 | 抽到海克斯时占比 |
| --- | --- | --- |
| 正面 · 青铜（12 条） | 1.00% | 25.0% |
| 正面 · 白银（39 条） | 1.19% | 29.8% |
| 正面 · 黄金（12 条） | 0.30% | 7.5% |
| 正面 · 传说（4 条） | 0.006% | 0.1% |
| 负面 · 代价（15 条） | 1.50% | 37.5% |
| 商店代币（1 ~ 代币上限枚） | 10% | — |

品质这一列是「每条词条权重 × 条数」算出来的（青铜 60 / 白银 22 / 黄金 18 / 传说 `海克斯.传说词条权重`），
已经抽满的、以及被三选一禁掉的词条会临时退出池子，所以实际比例会比表里略有浮动。

**拿取上限**：普通海克斯最多同时持有 **4 条**、技能解锁词条最多 **1 条**（同一条词条叠层不占额外名额）。
满了之后再拿到新词条，会弹出替换面板 —— 点一条旧的把它**连效果一起移除**，新词条顶上；点新词条则放弃。
上限数值可以在服务器配置里调整。

技能单独有一块 HUD 挂在**屏幕正中间正下方**：一格一个技能，显示技能图标和这一格的能量消耗；
冷却中会把图标压暗、盖一层从上往下退去的遮罩，中间显示剩余秒数（不足 1 秒带一位小数）；
当前按 `H` 停在哪一个，那一格就用金色描边标出，HUD 上方一行写着当前技能名与按键提示。
能量不够时消耗数字变红、图标压暗；长按 `K` 把整个 mod UI 藏起来时它一起消失。
图标来自开源图标库 [game-icons.net](https://game-icons.net)（CC BY 3.0），构建时嵌入 dll，所以模组仍是单文件分发。

## 配置

配置项的分组名和条目名都是中文 —— mod 管理器的配置页直接显示这两级，写成英文玩家打开就是满屏英文。

改配置不用去翻 `.cfg` 文件：游戏里就能改。**`ESC` → 设置**（主菜单 → 设置也一样）打开的
原生设置页最上面会多一行「海克斯模组设置」，点它是完整的配置面板；也可以随时按 `F9` 直接打开。
面板里按分组列出全部配置项：开关 / 按键 / 单选排成两列，点一下切换、重绑、或往后翻一格（右键往前翻）；
**数值项是整行的输入框，一排只放一个**（左边名字、右边框）——
点一下框就能直接敲数字，**回车、点别处、或者直接关面板都会自动保存**，不用找保存按钮；
框里只认数字 / 小数点 / 负号，`退格` 删字，`ESC` 是「这次不填了」（配置里的值保持原样）。
**数值不设上下限**：填多少存多少，只有「最多三位小数」的精度取舍（跟框里显示的一致），
想要多极端的值直接填就行，没有会被夹回来的说法。
配置项列表最后有一行「恢复默认」：点右边那颗按钮，一键把上面这些**数值项**调回默认值（开关与按键不动），
改乱了不用一个个改回去。
行上只写配置项的名字，鼠标停在某一行上时面板底部会显示那一项的完整说明，所以列表不会被整句说明撑长。
列表最后面还有一段「商店调价」（见[商店](#商店)），逐件改商品单价的入口就在那里。

>
> 这次把 `行李箱.出海克斯概率` / `行李箱.负面词条权重` 换成了正面 / 负面两项，旧键同样会在启动时被清掉

>

> 上表里那几行数值项（代币、物价、开箱概率、抽取权重）会被改回默认值，

> 只有版本号变了才刷一次。BepInEx 只在「键不存在」时才写默认值，不做这一步的话，
> 老玩家的 `.cfg` 会永远停在旧数值上 —— 改代码里的默认值等于只有新玩家吃得到。
> 记账用的是一个隐藏项 `内部.配置版本`（由模组自己维护，不要手动改）。

## 上报日志

遇到 bug 想反馈时，在游戏里按 `F10`（可在「界面 / 上传日志」里改键；卡在主菜单、加载界面时也能按，它不依赖角色）：

1. 客户端把这一段拼成纯文本：**全房间快照**（mod 与游戏版本、场景、联机情况、**房间里每个角色**的词条与层数、
   扛人 / 昏迷 / 僵尸状态）、**词条触发统计**（本机每条词条本局触发了几次、累计影响了多少、被动在场多久 ——
   「某条词条好像没生效」的答案基本都在这，带 `※` 的是埋了点、显示 0 次就说明一次都没生效）、
   **全局机制状态**（防挂机开关与每人累计秒数、本机与全房间禁用名单、商店改价件数、本局阶段与时长）、
   **补丁体检**（哪几条 Harmony 补丁没打上、为什么 —— 「某个功能在游戏里毫无反应」的答案基本都在这）、
   **`.cfg` 原文**、**BepInEx 日志与游戏 `Player.log` 最近 10 分钟的那一段**
   （两份日志都没有时间戳，模组每 30 秒记一次文件长度，事后反推「十分钟前」落在第几个字节；
   各另有 256 KB / 512 KB 的上限兜底，刷屏日志也传不出几 MB）；
2. gzip 之后 POST 到更新源同目录下的 `report.php`（源码里依旧不写服务器地址，跟着构建时注入的更新源走）；
3. 服务器**原样存盘、不解压**，回一个 6 位数字编号（首位不是 0）—— 纯数字，手打不会看错；
4. 客户端立刻弹出一个「日志已上传」浮窗：**大号 6 位编号** + 「复制编号」 + 「确定」。编号同时写进剪贴板，
   **浮窗会一直停着，直到你点「确定」才关** —— 抄不全或者要让别人帮着发，都不会来不及；
5. 编号回头忘了也不要紧：`F9` 打开「海克斯设置」，列表最下面那节「日志上报 · 本机上传记录」里躺着最近几份编号
   （写着上传时间、大小、还剩几小时，**点一行就能再复制一次**）。这份记录和服务器一样只留 48 小时。

上传本身走了**两条互不相同的通道**（先 Mono 的 `HttpWebRequest`，不通再换 Unity 的 `UnityWebRequest`），
每条最多等 20 秒，屏幕上方一路报进度（「正在打包日志…」「正在上传日志… 已等 N 秒」）——
不会有「按了键之后一片安静、分不清是在传还是卡死」那种情况。两条都不通（断网、防火墙、服务器在维护）时，
报告会落到 **`BepInEx\HextechMod-report.txt`**，直接把这个文件发给作者效果一样
（只有失败才写；传得上去时不会在硬盘上留下这份带昵称的日志）。

报告存在服务器的 `/www/hextech-reports/<编号>/` 下，这个目录在**站点根目录之外** —— 用浏览器拉不到，只有 SSH 进得去；
同一个 IP 每天最多 20 份，**超过 48 小时的每天 00:00 自动删除**（所以拿到编号就尽快取件），作者侧取件：

```powershell
.\_tools\fetch-report.ps1 -Code 482915   # 拉回本地解压到 artifacts\reports\<编号>\，默认打印报告开头那一段
.\_tools\fetch-report.ps1 -List          # 编号想不起来了：列出最近 30 份（编号 + 时间 + 客户端摘要）
```

报告开头那几节就是给人看的：**全房间角色 → 词条触发统计 → 全局机制状态 → 补丁体检 → 配置**，先看它们定范围，
真要抠细节再往下翻 BepInEx / Unity 的日志尾部。

服务端脚本与站点配置也在仓库里：`server/report.php`、`server/nginx-hextech.conf`（站点只放行这一个脚本，不启用全站 `.php` 解析）。

**只有你自己按下 `F10` 才会传，模组不做任何自动上传。** 包里含**你和队友**的游戏昵称、房间人数、全房间的词条与你的这份配置，介意的话别按。

## 实现说明

- 词条效果由「玩家自己的客户端」施加在自己的角色上。游戏自带的 `CharacterAfflictions.AddAffliction`
  会自动把状态同步给其他客户端，所以强化效果在联机中其他人也能看到。
- 「坚韧之躯」「玻璃体质」无法只靠改数值实现，用 Harmony 前缀挂 `CharacterAfflictions.AddStatus`：
  只改动**本地自己的**角色受到的负面状态积累（`fromRPC` 的同步数据不重复削减），
  系数为 `0.75^坚韧层数 × 1.25^玻璃层数`。
- 同一套 `AddStatus` 前缀还负责四条专项抗性（皮糙肉厚 / 抗毒体质 / 隔热层 / 破咒者）、
  「冷血体质」的灼热豁免（`0.5^层数`）与「百毒不侵」：
  专抗只对各自那一种状态再乘一层（`0.7^层数` / `0.8^层数`）；百毒不侵把孢子压到
  `ZOMBIFICATION_SPORES_THRESHOLD` 的九成，并按掉 `CharacterAfflictions.willZombify` 的取值，
  就算孢子被别处（难度系数、回填数据）推过了线也不会变僵尸。
- 「送葬人」挂 `Character.RPCA_PassOut`：本地玩家附近有队友倒地时给自己回体力 + 加速，一次倒地只结算一次。
- 「抬轿人」在每帧读 `CharacterData.IsCarryingCharacter`：扛起时把移动速度乘上去、放下时除回来，
  乘了多少记在 `HextechState` 的计时器里，多拿一层时不会叠出重复的倍数。
- 「收藏家」的效果在 `HextechState.AccrueTokens` 里结算：代币积累速率乘以 `1 + 0.5×层数`。
  代币在这里**按帧连续累加**（不是「每满一个间隔 +1」），所以 1.5/分 这种非整数速率也能如实体现，
  HUD / 商店显示到一位小数（`HextechState.FormatTokens`，向下取整，显示的数一定买得起）；
  跨过整数时照旧弹一次「商店代币 +1」。消费仍按整数价扣，找零的小数留在账上。
- 「骨质疏松」走的是游戏自己的骷髅入口 `CharacterData.SetSkeleton(true)`（内部会发 PunRPC，所以联机中别人也能看到），
  同时把已攒的诅咒清零；之后的诅咒由上面那套 `AddStatus` 前缀封成 0 —— 骷髅形态原本只放行**伤势** / 诅咒 / 蛛网 / 石化 / 捕蝇草，
  封掉诅咒就等于把「日常状态」全免疫了。⚠ 放行的这几种里伤势被原版硬编码放大 **8 倍**
  （`isSkeleton && Injury → amount *= 8f`），所以骷髅明显更怕摔、怕箭 —— 羽落是比例减免，直接作用在放大 8 倍之后的
  伤势上（人形剩 0.02 份、骷髅剩 0.16 份，骷髅照样疼 8 倍）；只有「不死鸟」那种留**绝对量**的才把 ×8 除回来。
  回机场（`ResetForNewRun`）时把骷髅变回人形。
- 行李箱抽奖用到两个补丁：
  - `Spawner.SpawnItems` 前缀：对 `Luggage` 直接返回空列表，把原版掉落整体关掉（`RespawnChest` 除外）。
  - `Luggage.Interact_CastFinished` 后缀：在开箱者本地跑抽奖。槽位数与「原本该刷什么」用反射调用
    `Spawner.GetSpawnSpots` / `Spawner.GetObjectsToSpawn`，保证和原版完全一致。
  - 抽到的物资走 `PhotonNetwork.InstantiateItemRoom`，由房主生成；非房主把请求通过
    `HextechState.HextechRPC_SpawnLoot` 发给房主，位置由请求方算好，所以联机表现和普通掉落一致。
  - 每个箱子按 `PhotonView.ViewID` 记一个「已抽过」标记，防止同一次开箱被判定两次。
- 抽奖动画（`HextechRoll`）同样是纯代码 UGUI：42 个格子排成一条轨道，前 35 格随机填陪跑内容，
  中奖结果固定放在第 36 格，然后按 `EaseOutQuint` 从右往左滚到位，再高亮中奖格、弹出结果条。
  一次约 2.6 秒（滚动 `1.5` + 落定 `0.28` + 停留 `0.85`），只有海克斯会走这条路：
  开箱抽到物资 / 代币时连 `RollShow` 都不建，直接结算，省掉一段没人想看的时间。
  结果在调用方那边**先结算**（词条立即生效、物资立即生成），动画结束才播报，
  所以跳过、掉线、动画期间退游戏都不影响实际收益。
- 抽奖动画是**排队播放**的（`PlayQueue`）：动画播到一半又买了一张券、或者又开了一个行李箱，
  新抽奖不会打断当前这次，而是接到队尾等它播完再演 —— 连着开好几个箱子，每一次都会依次演完，
  不会被吞掉。多次播放的收尾回调（结算播报、商店刷新）会串起来一起执行。
- 「背包客」的扩容只认**滑稽背包**一种，而且只认**本地玩家背着的那个**：普通背包原版就 4 格
  （扩了看不出多），喷气背包 / 火箭背包本身没有物品格，火箭背包背上之后按住 E 是点火，
  动它的格子会出怪状态，所以扩容（数据格、轮盘切片、模型挂点、序列化）对它们等于不存在。
  老版本补丁给普通背包 / 火箭背包扩过容的，会在穿戴、开轮盘、同步时缩回原版 4 格。
- 这套扩容要同时改数据格、轮盘切片、序列化和模型挂点（见代码里的 `BackpackCapacity`）。
  轮盘切片的位置是预制体摆死的，扩到 6 格必须自己重排：拟合出原版那几格所在的圆，
  再把**全部切片（含第 0 片）**按新数量均分，半径按「相邻弦长不小于原版」放大，
  这样扩出来的格子既不会和邻居叠，也不会把第 0 片压住。
- `BackpackVisuals.RefreshVisuals` 的循环体写的是 `backpackSlots[i]`，所以补丁换掉的那个循环上界
  必须取「数据格数」和「挂点数」里**小的那个**：只按数据格数走，数据 6 格 / 挂点 4 个时直接越界，
  而它是在「背上 / 卸下背包」的协程里跑的，一抛就把收尾打断（表现：背包脱不下来、地上凭空多一个）。
- 卡片图标直接取 `Item.UIData.icon`（`Texture2D`），用 `RawImage` 显示；没走 `Item.GetIcon()`，
  那个要读设置管理器，早期可能为空。没有图标的商品（抽奖券）用稀有度符号当占位。
- UI 的圆角/光晕/圆环/渐变贴图都是运行时按半径生成并缓存的一次性 `Sprite`，不依赖任何美术资源。
- 三选一面板是纯代码构建的 UGUI，不使用 `EventSystem`，直接做矩形命中检测，
  以便在任何输入模块配置下都能点击。每张卡片右下角是一个「刷新」按钮，命中检测时
  先判按钮再判整张卡，否则点刷新会被「点卡片 = 选择」吃掉；**每张卡每次机会只能刷一次**
  （`CardView.RerollUsed`），刷新时会把当前摆着的几张一起排除掉，所以不会刷出重复项。
- 三选一的「跳过」是一个显式状态，而不是「什么也没发生」：面板只区分 `Hide()`（选过了，这次用掉）
  和 `Dismiss()`（按 `ESC` 或窗口被游戏关掉，这次没选），后者会回调调用方。
  管理器只在**真的选中**时才把这次从待选队列里出队，所以「跳过的会叠到下一次篝火」是队列
  自然积累的结果，不需要额外的计数器。玩家自己收起来的面板不会自己再弹（否则按 `ESC` 等于没按），
  要等按 `Y`、或者下一次篝火把新的一项推进队列。
- **收起来再打开看到的是原来那几张**：每次机会带一个编号（`PendingChoice.Key` →
  `HextechPanel.Show(offerKey, …)`），编号没变时面板原样摆回上次的牌和「哪张刷过、刷成了什么」，
  连抽牌函数都不会被调用；只有真的选中（`Hide()`）才作废这次摆过的牌。
  没有这一层的话，`ESC` 收起来再按 `Y` 打开就等于**无限刷新**（2026-09-13 修，玩家反馈上来的）。
- 篝火触发用 Harmony 挂在 `Campfire.Light_Rpc` 上，只认 `updateSegment = true` 的那次点火
  （新角色入队时游戏会补一次同步点火，那种不算），并按「该篝火将要推进到的阶段」记发奖标记，
  所以同一阶段反复点火、或者退回去再点一次都不会重复拿。
- 防挂机的判定放在**房主**的一帧逻辑里（`HextechManager.Update` → `CampfireZombieGuard`）：
  遍历 `Character.AllCharacters`，按「离任意一个**点着**的 `Campfire` 中心（`Campfire.Center()`）是否在半径内」
  给每个人累计「净待在圈里的时间」—— 在圈里累加、出圈按同样的速度往回退（退到 0 为止）—— 攒满就召唤。
  ⚠️ 挑篝火要同时卡三条：篝火与玩家**在同一张 Unity 场景**里（机场那张图跑图时可能还挂着，坐标又压在上机 / 落地那一片）、
  玩家自己不在机场场景里（按**角色所在场景**判断，不是只看「活动场景」）、并且 `state == Campfire.FireState.Lit`（真在烧）
  —— 游戏里 `Lit` 的口径是 `state == Lit || forceLit`，`forceLit` 的装饰篝火不冒火苗，按 `Lit` 算就会出现
  「站在没有火的地方被招僵尸」。
  判定放房主侧既是必须的（往世界里实例化网络物体
  只有房主做得了），也顺带不怕挂机那个人的客户端卡住或降帧。
  召唤完全照抄原版 `MushroomZombieSpawner.Spawn()`（`PhotonNetwork.Instantiate(预制体名, 位置, 朝向, 0, null)`），
  所以僵尸的注册（`ZombieManager.RegisterZombie`）、沉睡 / 破土、找人追人、咬人都走原版逻辑；
  锁定目标用原版自己的广播 RPC `RPCA_SetCurrentTarget`（`SetCurrentTarget` 是 `protected`，而且只在目标变了时才转发），
  生成距离按预制体上报的 `distanceToEnable` 收窄，保证落在僵尸会醒的范围内 —— 否则它会一直在土里睡着。
- 扛人兜底放在**本地玩家**那一帧（`HextechManager.Update` → `CarryGuard`）：原版能扛的只有「完全昏迷」的队友，
  而**被扛者醒来时原版什么都不做** —— `Character.UnPassOutDone` 只清 `fullyPassedOut` / `passedOut`，
  `CharacterCarrying.Update` 只在**扛人者自己死亡**时自动放下，全游戏只有 `RPCA_StartCarry` / `RPCA_Drop` 会写 `carrier`；
  手动放下又只剩 `Interaction.DoInteractableRaycasts` 里「扛着人 **且** 当前选中槽是背上那个槽」这条特殊分支
  （扛起时 `CharacterRagdoll.ToggleCollision(false)` 已经把被扛者的碰撞体全关掉，普通射线根本扫不到人）。
  于是队友醒了之后人就一直挂在肩上、按什么都放不下来 —— `Core/CarryGuard.cs` 补的就是这一半：
  肩上的人一旦不再完全昏迷或已经死亡，就调原版自己的 `Character.BreakCharacterCarrying(true)` 广播放下。
  这条 RPC 打在扛人者的 PhotonView 上、必须由扛人者的客户端发出（联机时「扛人的那方」也得装模组），
  同一个目标 3 秒内只尝试一次（RPC 是异步的，避免刷屏）。
- 上报日志（`Core/LogReporter.cs`）：读日志必须 `FileShare.ReadWrite` —— 那两个文件此刻正被游戏和 BepInEx 写着，独占打开会直接失败；
  配置不去遍历 `ConfigFile.Entries`（BepInEx 里是 internal），直接附 `.cfg` 原文，反正默认每次改动都会立刻落盘；
  Unity 日志就是 `Application.persistentDataPath` 下的 `Player.log`（PEAK 的存档目录即 `…LocalLow\LandCrab\PEAK`）。
  上传用 `octet-stream` 原始字节（客户端自己 gzip），服务端不解压、原样存 `.gz` —— 省掉一整套 multipart 解析，
  也不受 PHP `upload_max_filesize` 的约束。地址由更新源推导（把 `version.json` 换成 `report.php`），源码里依旧不出现服务器地址。
  服务端（`server/report.php`）把报告存在 `/www/hextech-reports/<编号>/`（docroot 之外），**只留 48 小时**：每天 00:00 由 `www` 用户的
  crontab 跑一次 `php /www/wwwroot/hextech/report.php`（脚本的 CLI 分支只做清理，HTTP 那条路不受影响），
  删掉超过 48 小时的报告目录、顺带清 7 天前的限流计数；上传那条路另留一条「隔天顺手清一次」的兜底。
  ⚠️ 宝塔面板里保存计划任务会重写 crontab（和它保存站点设置会重写那份 `nginx` 配置一个道理），被冲掉了照上面那句重新加一条即可。
  编号到玩家手里这条路：上传成功 → `UI/HextechReportCodeHud`（模态浮窗，走 `HextechWindowHost` 解锁鼠标，点「确定」才关）
  → 同时由 `Core/ReportHistory` 记进 `.cfg` 同目录的 `HextechMod-reports.txt`，设置面板「日志上报」那一节读的就是它（48 小时过期）。
- 中文字体：游戏主字体只有拉丁字形表，直接拿来用中文全是方框。
  mod 会把游戏自带的 `FontFallbackSwapper.simplifiedChineseFont` 挂进主字体的 fallback 表，
  并且每帧校正一次 —— UI 是插件加载时就建好的，那时 `FontFallbackSwapper` 可能还没出现。
- 一局结束的判定是「加载了 `Airport` 场景」，此时清空全部 `HextechState`：
  除了词条/层数/技能/能量，还会把本局改过的移动数值还原、并摘掉本局挂上去的 affliction。

## 构建

需要 .NET SDK 10（或更高），以及本机安装的 PEAK。

1. 复制 `Config.Build.user.props.template` 为 `Config.Build.user.props`，按需修改路径。
2. 构建：

```sh
dotnet build
```

若 `DeployModFiles` 为 `true`，产物会自动复制到 `PEAKBepInExDir/plugins/`。

## 一键安装器

仓库带了一个图形化安装器（`src/HextechMod.Installer`），**模组本体是内嵌进去的**，
所以一个 exe 就能发给别人用：

```sh
dotnet build -c Release src/HextechMod.Installer/HextechMod.Installer.csproj
```

产物在 `./artifacts/bin/HextechMod.Installer/release/HextechModInstaller.exe`。

它做的事：

- **自动检测游戏位置**：从注册表拿 Steam 安装目录，解析每个库的 `steamapps/libraryfolders.vdf`，
  逐个库找 `steamapps/common/PEAK`；实在找不到还能手动选 `PEAK.exe`。
- **自动补依赖**：没装 BepInEx 就从 Thunderstore 下载 `BepInExPack_PEAK 5.4.75301` 解压到游戏根目录；
  已经装过就跳过，不动你原有的框架。
- **一键安装**：联网问一次服务器上的最新版本，把 dll 下载回来并校验 SHA256，放进 `BepInEx/plugins/`。
  **安装器不再内置 mod 本体** —— 模组只从服务器取，所以这一步必须联网；
  连不上时会把原因写清楚（网络 / 代理），而不是拿一份旧 dll 糊过去。
  窗口一开就会把服务器版本和更新公告打在日志区，「HextechMod」那一行也会标出能更新到几版。
- **一键卸载**：删掉模组 dll；只有勾了「一并移除 BepInEx 框架」才会连框架一起清，
  而且仅在框架确实是安装器装的前提下才动手，plugins 里还有别的插件时会先警告。

界面配色和排版直接复用模组在游戏里那套面板（见 `UiFactory`），看着是一路的。

实现上几个关键点：

- 目标框架是 .NET Framework 4.8 —— Win10 1903+ / Win11 全都自带，玩家不用另装运行时；
  换成 net8 自包含发布的话，一个安装器要一百多兆。
- 游戏一般在 `Program Files` 下，manifest 里直接申请了管理员权限，免得装到一半才失败。
- 装/卸前会检查游戏是不是开着 —— `winhttp.dll` 被占用时写不进去。
- 解压会自动剥掉 Thunderstore 多套的那层 `BepInExPack_PEAK/` 目录，
  并跳过 `icon.png` / `manifest.json` / `README.md` 这些页面素材，游戏根目录不会留垃圾。

## 打包到 Thunderstore

```sh
dotnet build -c Release -v d
```

产物位于 `./artifacts/thunderstore/`。
